# Admin Map Regions

- HASHI-237은 기획 `MAP_MAIN`의 관광 지역 클러스터 운영 데이터 입력과 서버 `docs/map/admin-regions.md` 계약을 연결한다. 사용자 지도 동작·실제 지역 seed·위치 검증은 변경하지 않는다.
- ADMIN 전용 `/admin/restaurants/map-regions`. 식당 관리에서 진입하며 목록은 비활성 지역을 포함해 서버의 displayOrder/ID 정렬, 0-based page, size=20, totalCount를 사용한다.
- 지역 PUT은 전체 교체다. 편집 시작 시 목록의 모든 값을 보존하고 code는 수정하지 않는다. 새 지역은 비공개이며 실제 좌표를 임의로 채우지 않는다. 같은 code로 저장하면 기존 ID와 식당 소속을 유지한다. 삭제 대신 비공개로 저장한다.
- 빈 좌표·범위 초과·소수 6자리 정밀도 손실·역전 경계·대표 위치 미포함을 차단한다. 공개 지역은 각 축 최대 1도. 실제 지원 영역과 지도 설정은 서버가 검증하고 011/017 메시지를 표시하며 실패 입력은 유지한다.
- 저장 중 중복 제출·닫기를 막는다. 목록 갱신으로 열려 있는 편집 초안을 덮어쓰지 않는다. 저장 성공 후 관리자 목록과 배정 선택 목록을 무효화한다. 서버는 version 충돌 검증 없이 최종 PUT을 적용한다.
- 기존 식당 수정의 기본 정보에서 관광 지역을 명시 선택해 배정한다. 비활성 지역도 선택 가능하며 다음 페이지는 더 불러오기로 조회한다. 배정값을 자동 추론하지 않는다. 현재 소속 조회 API가 없으므로 선택의 초기값을 현재 소속처럼 표시하지 않는다.
- 배정과 해제는 확인 모달 후 식당 정보 저장과 별도로 PUT한다. 해제는 `{mapRegionId:null}`을 명시한다. 주소·좌표·revision을 수정하지 않는다. 실패 시 선택과 미저장 식당 입력을 유지하며 이탈 시 요청을 중단하고 늦은 결과를 무시한다. 이미 서버에 접수된 쓰기는 취소로 되돌아가지 않을 수 있다.
- 자동 검증은 정밀도·경계 예외, 전체 값 보존, 실패 복구·중복 제출, 명시 null 계약, 잘못된 배정 응답 및 이탈에 집중한다. 단순 UI·스타일 테스트는 추가하지 않는다.
- 서버 후속: OpenAPI의 배정 요청·응답에 명시 null 타입이 누락되어 해당 경계만 보완했다. 스키마 수정 후 generated 타입으로 교체한다.
- 실서버 쓰기 없이 목록 조회와 화면 진입을 확인한다. 실제 지역 등록·공개·비공개, 배정·해제 및 사용자 지도 집계는 승인된 데이터로 후속 확인한다.
