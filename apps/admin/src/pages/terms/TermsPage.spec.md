# Admin Terms

- 기획: `HASHI-PLAN/02_PRODUCT_SPEC/SPRINT-001_ADDITIONAL_FEATURES.md` §10. 서버 계약: `HASHI-SERVER/docs/support/terms.md` 및 관리자 OpenAPI.
- 관리자만 `/admin/terms`, `/admin/terms/new`, `/admin/terms/:termsId`에 접근한다. 목록 유형 및 페이지는 URL query에 보존한다.
- 서버의 8개 유형 및 현재 버전 ID를 조회하고, 선택 유형의 버전 이력을 ID 내림차순으로 20개씩 조회한다. 현재 적용 버전이 없어도 관리 대상에서 제외하지 않는다.
- 생성·상세·수정은 별도 페이지다. 초안만 수정·삭제·게시하며, 기존 초안의 유형은 변경할 수 없다. CURRENT/ARCHIVED는 읽기 전용이다.
- 제목 1~100자, 버전 `[A-Za-z0-9][A-Za-z0-9._-]{0,49}`, 시행일 1000~9999년 유효 날짜, 조항 1~200개를 검증한다. 조항 제목 1~100자, 내용 필수이며 제목과 내용 합계는 UTF-16 기준 100,000자 이하다. 공백뿐인 제목·조항은 저장하지 않는다.
- 조항은 일반 텍스트이며 줄바꿈과 순서를 보존한다. HTML을 실행하거나 입력을 임의로 trim하지 않는다. 버전의 대소문자 구분 및 유형 내 중복은 서버가 판단하며 서버 오류를 표시하고 입력을 유지한다.
- 새 초안 저장 성공 후 상세 URL로 replace 이동한다. 게시 실패 후 재시도는 이미 생성된 초안에 수행한다. 중복 제출을 막는다.
- 게시 전 별도 확인을 받는다. 미래 시행일도 예약 게시가 아니라 즉시 적용됨을 안내한다. 성공 시 유형 목록과 해당 유형의 이력·이전 버전 상세 캐시만 무효화하여 이전 CURRENT 상태가 남지 않게 한다. 다른 유형의 이력·상세는 무효화하지 않는다. 실패 시 기존 현재 버전을 낙관적으로 바꾸지 않는다.
- 저장 실패 및 상세 재조회 실패 시 편집 상태를 유지한다. 미저장 이동은 확인하고, 새로고침·닫기는 beforeunload로 확인한다.
- 재조회로 서버 본문 변경을 확인하거나 미저장 편집 중 게시 상태로 바뀌면 입력을 유지하고 저장·게시를 차단한다. 현재 입력을 잃는다는 안내와 함께 관리자가 직접 최신 저장본으로 교체한 뒤 확인하도록 한다.
- 중요한 예외만 자동 검증한다: 중복 버전 저장 실패 및 재조회 실패 후 입력 유지, 중복 생성 방지와 게시 재시도, 게시 실패 시 현재 버전 캐시 유지, 게시 성공 후 이전 버전 재조회, 게시 버전 수정·삭제 차단.
