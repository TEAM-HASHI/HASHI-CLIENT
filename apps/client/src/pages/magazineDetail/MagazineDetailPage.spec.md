# 매거진 상세 페이지

## 작업 범위

- 경로: `/magazines/:magazineId`
- Figma: `8317:36532`
- 기획 명세: `HASHI-PLAN/02_PRODUCT_SPEC/MAGAZINE/MAGAZINE_DETAIL/MAGAZINE_DETAIL.md`
- HASHI-227: 상세 조회와 좋아요 등록·취소를 실제 API에 연동한다.
- 개발 Swagger user OpenAPI와 서버 origin/develop의 매거진 상세 응답을 기준으로 구현한다.
- 임시 상세 데이터와 운영 준비 중 분기는 제거하며 개발·운영 모두 같은 API를 사용한다.

## 동작

- 상단 헤더는 고정하고 본문은 헤더 높이 `75px` 아래에서 시작한다.
- 뒤로가기는 브라우저 방문 기록이 있으면 이전 화면으로 이동한다. 브라우저 뒤로가기인 `POP` 이동에서는 기존 전역 스크롤 초기화를 생략하는 매거진 목록 예외를 유지한다.
- 직접 URL로 진입해 이전 방문 기록이 없으면 `/magazines`로 이동한다.
- 목록의 배너와 카드는 상세 경로로 이동하며, 상세 정보는 URL의 양의 정수 magazineId로 조회한다. 미리보기용 location.state는 전달하거나 사용하지 않는다.
- 커버 이미지는 HDS `Carousel`을 사용해 가로로 전환하고 현재 이미지 번호와 전체 이미지 수를 표시한다.
- 커버 이미지가 없거나 로딩에 실패하면 `ImageFallback`을 표시한다.
- 로그인 회원의 좋아요는 요청 시 하트와 수를 낙관적으로 갱신하고 실패 시 이전 값으로 되돌린다. 성공 응답의 liked와 likeCount로 최종 상태를 맞춘다.
- 요청 중에는 버튼을 비활성화하며, 화면 상태가 반영되기 전의 연속 클릭도 동기 잠금으로 막는다.
- 비로그인 사용자는 좋아요 API를 호출하거나 값을 변경하지 않고 로그인 바텀시트를 표시하며 로그인 후 돌아올 상세 경로를 전달한다.
- 식당 카드는 데이터로 전달받은 이미지 항목만 렌더링하며, 이미지 배열이 비어 있으면 임의의 이미지 슬롯을 만들지 않는다.
- 식당 카드를 선택하면 `getRestaurantDetailPath`로 생성한 `/restaurants/:restaurantId` 경로로 이동한다.
- 연결된 식당이 없으면 식당 목록 영역을 렌더링하지 않는다.

## 데이터 경계

- API 함수, query options, 좋아요 mutation, 응답-to-view model 변환은 pages/magazineDetail에서 관리한다.
- 상세·좋아요 응답 계약은 generated OpenAPI 타입에서 가져오며, 런타임에 검증한 필드만 필수 타입으로 좁힌다.
- 상세 query key는 매거진 ID와 인증 세션 버전을 포함한다. 실제 로그인·로그아웃 시 버전이 변경되어 이전 계정의 개인화 데이터를 재사용하지 않으며 토큰 자체는 key에 넣지 않는다. 같은 세션의 토큰 재발급은 버전을 변경하지 않아 진행 중인 좋아요 요청을 유지한다. 같은 토큰 값으로 재로그인해도 이전 요청은 무효화한다.
- 매거진 또는 viewer가 바뀌면 상세 UI를 다시 마운트한다. 이전 요청은 원래 캐시만 대상으로 하며, 화면 이탈·세션 변경 후 좋아요 응답과 오류 안내를 현재 화면에 반영하지 않는다.
- 좋아요 요청 전 상세 조회를 취소하여 조회 응답이 낙관적 상태를 덮어쓰지 않게 한다. 화면 이탈로 요청이 취소되어도 원래 상세 캐시는 무효화하여 재진입 시 서버 상태를 다시 조회한다. 좋아요 정보를 표시하지 않는 목록·배너는 불필요하게 재조회하지 않는다.
- cardNewsImages가 있으면 displayOrder 순서와 이미지 상태를 사용한다. READY의 defaultSource, asset이 없는 항목의 legacyUrl을 사용하고 처리 중·실패 항목은 fallback으로 표시한다. 길이가 다른 cardNewsImageUrls와 인덱스를 맞추지 않는다.
- wrapper가 없는 기존 응답은 cardNewsImageUrls를 사용한다. 캐러셀의 기존 고정 비율과 디자인은 유지한다.
- 연결 식당은 상세 응답으로 렌더링하며 식당별 추가 조회는 하지 않는다. 없는 영업시간·가격은 정보 없음으로 표시하고 휴무와 0원 가격을 구분한다.

| API                                         | 역할                                       |
| ------------------------------------------- | ------------------------------------------ |
| GET /api/v1/magazines/{magazineId}          | 상세 정보와 내 좋아요 여부, 연결 식당 조회 |
| POST /api/v1/magazines/{magazineId}/likes   | 좋아요 등록                                |
| DELETE /api/v1/magazines/{magazineId}/likes | 좋아요 취소                                |

## 기획 명세와의 차이

- 기획에는 작성자명이 있으나 현재 디자인에는 작성자 영역이 없다. 디자인 기준으로 작성자명은 표시하지 않으며 추가 구현 대상에 포함하지 않는다.
- 유효하지 않은 ID와 상세 404는 `매거진을 찾을 수 없습니다.` 및 돌아가기 액션을 표시한다.
- 상세 조회 실패는 공통 오류 문구와 재시도를 제공한다. 좋아요 실패는 공통 토스트를 표시하고 기존 하트·수를 원복한다.

## 검증

- 자동 테스트는 세션·매거진 변경 시 이전 응답 차단, 좋아요 중복 요청·실패 원복·캐시 재진입, 조회 오류와 이미지 응답 처리의 예외 상황을 검증한다.
- 화면 배치와 캐러셀 터치 동작은 수동 확인하고 검증 결과는 PR에 기록한다.
