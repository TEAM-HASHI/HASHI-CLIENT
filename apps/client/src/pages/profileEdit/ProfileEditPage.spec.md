# 프로필 수정 페이지 명세

Jira: HASHI-201

API 연동: HASHI-225

## 작업 범위

- 인증 사용자가 마이페이지의 `수정` 버튼을 통해 `/profile/edit`로 이동합니다.
- 프로필 생성 화면과 공통 프로필 이미지·입력 필드·검증 UI를 재사용합니다.
- 내 정보 수정, 프로필 사진 삭제, 중복 검사와 프로필 이미지 asset 업로드를 연동합니다.

## 공통 프로필 폼

- 공통 프로필 UI와 폼 상태는 `features/profile`에서 관리합니다.
- 필드 순서는 닉네임, 영문 이름(선택), 연락처, 이메일, 생년월일입니다. 영문 이름은 기존 조회값을 표시하고 최대 20자까지 수정할 수 있습니다. 생성 화면의 영문 이름 입력은 유지합니다.
- 수정 화면은 `GET /api/v1/users/me`로 조회한 프로필 전체 정보를 초기값으로 사용합니다.
- 저장 버튼은 필수값이 유효하고 초기값에서 변경되었으며, 중복 검사 대상 필드가 모두 사용 가능한 경우에만 활성화됩니다.
- 생년월일은 오늘을 제외한 과거 날짜만 허용합니다. 닉네임과 이메일 입력 제한은 서버 계약의 50자와 255자입니다.
- 초기값과 변경 비교 기준은 폼이 마운트된 시점의 응답으로 고정합니다. 재조회 응답은 작성 중인 입력을 덮어쓰지 않습니다.
- 최초 조회 실패만 오류 화면으로 전달합니다. 기존 데이터가 있는 백그라운드 재조회 실패에서는 폼을 언마운트하지 않고 입력값을 유지합니다. 내 정보 Query는 오류를 자동으로 throw하지 않고 페이지에서 데이터 유무를 기준으로 처리합니다.
- 닉네임 중복·익명 닉네임 예약어 여부는 서버가 판단합니다. 프론트는 예약어 목록을 관리하지 않고 서버에서 내려준 오류 메시지를 표시합니다.
- 이미지 변경은 draft의 `profileImageChange`에 `keep`, `replace`와 파일, `delete`로 구분해 전달합니다.
- 입력 영역과 하단 버튼 사이에는 최소 70px의 여백과 액션바 상단 45px의 여백을 합산해 확보합니다. 버튼 아래 여백은 48px와 safe area를 반영합니다.

## API 연동 및 예외

| API                                     | 용도                                                                                    |
| --------------------------------------- | --------------------------------------------------------------------------------------- |
| `PATCH /api/v1/users/me`                | 변경된 닉네임, 영문 이름(nameEng), 연락처, 이메일, 생년월일 및 profileImageAssetId 저장 |
| `DELETE /api/v1/users/me/profile-image` | 저장 시 기존 사진 삭제                                                                  |
| `POST /api/v1/users/availability`       | 변경된 닉네임, 연락처, 이메일의 사용 가능 여부 검사                                     |
| `POST /api/v1/media/assets`             | PROFILE asset 및 원본 업로드 URL 발급                                                   |
| 업로드 URL                              | 발급 응답의 메서드와 필수 헤더로 원본 전송                                              |
| `POST /api/v1/media/assets/complete`    | 원본 업로드 완료 통지                                                                   |
| `GET /api/v1/media/assets?assetIds=...` | 이미지 처리 상태 확인                                                                   |

- 새 이미지와 이미지 삭제 여부는 저장 전까지 폼의 변경 상태로만 관리합니다.
- 사진 교체는 원본 업로드 후 READY를 확인한 뒤 PATCH합니다. PROCESSING은 1초 간격으로 최대 30회 재조회하고 처리 실패 또는 대기 초과는 실패 처리합니다.
- 업로드까지 성공한 동일 파일은 같은 세션의 저장 재시도에서 asset ID를 재사용합니다. 서버가 asset 부재, 만료 또는 연결 상태 오류를 반환하면 재사용 정보를 버립니다.
- 기존 생성 화면의 fileKey 업로드 계약은 변경하지 않습니다. 수정 화면은 현재 개발 Swagger와 서버의 asset 계약을 사용합니다.
- PATCH는 마지막으로 저장에 성공한 정보와 비교해 변경 필드만 보내고 생년월일은 YYYY-MM-DD, 연락처는 숫자로 전송합니다. 영문 이름은 앞뒤 공백을 제거해 nameEng로 보내고 기존 값을 비우면 빈 문자열을 보내 삭제합니다. 미변경 시 생략하고 기존 이미지 URL은 전송하지 않습니다.
- PATCH 성공 후 사진 삭제가 실패해도 저장 비교 기준은 갱신합니다. 사용자가 원래 값으로 되돌린 뒤 재시도하면 그 값도 서버에 반영하며, 입력 폼의 초기값이나 작성 중인 값은 바꾸지 않습니다.
- 사진 삭제와 정보 수정은 별도 API입니다. 정보 수정 후 사진을 삭제하며, 부분 성공 시에도 해당 세션의 내 정보와 프로필 요약 캐시를 무효화합니다. 프론트에서 원자성을 보장하거나 성공한 변경을 롤백하지 않습니다.
- 저장 성공 시 내 정보와 마이페이지 프로필 요약 캐시를 무효화하고 `/mypage`로 이동합니다.
- 중복 검사는 형식 검증 통과 후 500ms 추가 입력이 없거나 blur 시 실행합니다. 기존 값과 달라진 필드만 검사하고 원래 값으로 되돌리면 재검사하지 않습니다. 검사 중 또는 재검사 전에는 저장을 차단해야 합니다.
- 중복 검사 결과는 필드, 값, 세션별 Query로 구분합니다. 이전 값의 지연 응답은 현재 필드에 반영하지 않습니다. 검사 실패 시 저장을 차단하며 같은 값에서 blur하면 다시 검사합니다.
- 사용 불가 응답과 저장 시 USER-001, USER-002, USER-003은 서버 메시지를 해당 필드에 표시합니다. COMMON-400의 필드별 reason도 폼 필드로 매핑합니다. 생성과 수정의 오류 매핑은 features/profile에서 공유합니다.
- 저장 실패 시 입력값과 미리보기를 유지하고 공통 오류를 폼에 표시합니다. USER-005 또는 인증 종료 시 인증과 캐시를 정리하고 로그인 안내 화면으로 이동합니다.
- 저장 중 입력, 사진 변경, 뒤로가기 및 저장 버튼을 잠그며 동기 잠금으로 중복 제출을 차단합니다. 같은 세션의 앱 내부 이동을 차단합니다.
- 세션 변경이나 언마운트 시 진행 중 요청을 중단하고 이전 응답이 새 세션의 캐시와 화면을 바꾸거나 후속 삭제를 실행하지 않도록 합니다. 서버에 도달한 요청의 처리를 취소한다고 보장하지는 않습니다.
- 기획 개별 문서의 사진 즉시 삭제·`/mypage/profile/edit` 경로와 달리 사용자 합의에 따라 저장 시 반영·`/profile/edit`을 유지합니다. 익명 닉네임도 서버가 판단하며 별도 프론트 예약어 목록을 만들지 않습니다.

## 코드 역할

- `useProfileEditPage`: 폼, 중복 검사 결과, 입력 필드와 제출 이벤트 조립
- `useProfileEditMutation`: 저장 순서, 마지막 저장값, 이미지 재사용, 세션 보호, 이탈 차단 및 캐시 갱신
- `features/profile`의 `useProfileAvailability`와 `checkProfileAvailability`: 생성 및 수정의 필드별 중복 검사, 응답 경합, 오류 문구와 blur 연결을 공유하며 수정 화면은 초기값을 검사에서 제외합니다.

## 후속 확인

- 기획 스프린트 문서의 영문 이름 수정 제외 항목과 달리, 사용자 요청 및 최신 개발 서버의 nameEng 계약에 따라 수정 기능을 활성화했습니다.
- 정보 수정과 사진 삭제를 원자적으로 처리해야 한다면 서버에 통합 계약이 필요합니다.
- 실제 개발 계정으로 이미지 처리 상태 전이와 저장 후 조회를 종단 검증합니다. 자동 검증에서는 실제 사용자 데이터를 변경하지 않습니다.

## 수동 검증

- 마이페이지 수정 버튼에서 `/profile/edit`로 이동합니다.
- 닉네임, 영문 이름, 연락처, 이메일, 생년월일, 프로필 이미지가 초기값으로 표시됩니다.
- 변경 전에는 저장 버튼이 비활성화됩니다.
- 기존 값 중 하나를 유효하게 변경하고 필요한 중복 검사를 마치면 저장 버튼이 활성화됩니다.
- 뒤로가기 버튼은 변경값을 버리고 마이페이지로 이동합니다.
- 중요한 예외 테스트는 중복 검사 응답 경합 및 재시도, 이미지 처리 실패 및 중단, 부분 저장 후 재시도, 중복 제출, 세션 변경 보호를 대상으로 합니다. 단순 UI 테스트는 추가하지 않습니다.
- 부분 저장 후 원래 값으로 되돌려 재시도하는 경우는 기존 통합 테스트를 강화했습니다. 백그라운드 재조회 실패에도 입력이 유지되는 경우는 전역 오류 throw 설정을 포함한 회귀 테스트로 검증합니다.
