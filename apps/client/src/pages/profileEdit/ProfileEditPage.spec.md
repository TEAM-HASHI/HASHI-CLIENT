# 프로필 수정 페이지 명세

Jira: HASHI-201

## 작업 범위

- 인증 사용자가 마이페이지의 `수정` 버튼을 통해 `/profile/edit`로 이동합니다.
- 프로필 생성 화면과 공통 프로필 이미지·입력 필드·검증 UI를 재사용합니다.
- 이번 범위에는 프로필 수정 API 연동을 포함하지 않습니다.

## 공통 프로필 폼

- 공통 프로필 UI와 폼 상태는 `features/profile`에서 관리합니다.
- 필드 순서는 닉네임, 영문 이름(선택), 연락처, 이메일, 생년월일입니다. 영문 이름은 피그마 디자인 기준으로 유지하며 조회한 값을 초기값으로 사용하고 변경 여부에 포함합니다.
- 수정 화면은 `GET /api/v1/users/me`로 조회한 프로필 전체 정보를 초기값으로 사용합니다.
- 저장 버튼은 필수값이 유효하고 초기값에서 변경된 경우에만 활성화됩니다.
- 초기값과 변경 비교 기준은 폼이 마운트된 시점의 응답으로 고정합니다. 재조회 응답은 작성 중인 입력을 덮어쓰지 않습니다.
- 닉네임 중복·익명 닉네임 예약어 여부는 서버가 판단합니다. 프론트는 예약어 목록을 관리하지 않고 서버에서 내려준 오류 메시지를 표시합니다.
- 이미지 변경은 draft의 `profileImageChange`에 `keep`, `replace`와 파일, `delete`로 구분해 전달합니다.
- 입력 영역과 하단 버튼 사이에는 최소 70px의 여백과 액션바 상단 45px의 여백을 합산해 확보합니다. 버튼 아래 여백은 48px와 safe area를 반영합니다.

## 후속 연동 및 정책 확인

- 프로필 수정 API 연동 전까지 유효한 저장 요청은 `ComingSoonDialog`로 안내합니다.
- 새 이미지와 이미지 삭제 여부는 저장 전까지 폼의 변경 상태로만 관리합니다.
- API 연동 시 이미지 변경을 포함한 프로필 변경값을 하나의 저장 mutation으로 반영하고, 필드 오류 매핑과 성공 후 query invalidation을 추가합니다.
- 저장 성공 시 내 정보와 마이페이지 프로필 요약 캐시를 무효화하고 `/mypage`로 이동해야 합니다.
- 중복 검사는 형식 검증 통과 후 500ms 추가 입력이 없거나 blur 시 실행합니다. 기존 값과 달라진 필드만 검사하고 원래 값으로 되돌리면 재검사하지 않습니다. 검사 중 또는 재검사 전에는 저장을 차단해야 합니다.
- 현재 수정 저장·중복 확인 API는 연동하지 않습니다. 저장 중 입력 잠금과 서버 필드 오류 처리는 해당 연동 시 적용합니다.
- 기획 개별 문서의 사진 즉시 삭제·`/mypage/profile/edit` 경로는 기존 확정 사항인 저장 시 일괄 반영·`/profile/edit`과 차이가 있습니다. 스프린트 명세의 영문 이름 제외 항목 대신 피그마 디자인을 따릅니다.

## 수동 검증

- 마이페이지 수정 버튼에서 `/profile/edit`로 이동합니다.
- 닉네임, 영문 이름, 연락처, 이메일, 생년월일, 프로필 이미지가 초기값으로 표시됩니다.
- 변경 전에는 저장 버튼이 비활성화됩니다.
- 기존 값 중 하나를 유효하게 변경하면 저장 버튼이 활성화됩니다.
- 뒤로가기 버튼은 이전 화면으로 이동합니다.
