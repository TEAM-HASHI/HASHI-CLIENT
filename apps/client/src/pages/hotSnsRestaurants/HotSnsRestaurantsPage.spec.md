# SNS 맛집 리스트 페이지 명세

## 목적

홈에서 일부만 노출하는 SNS 인기 식당을 전체 목록으로 탐색하고, 원하는 식당의 상세 화면으로 이동할 수 있게 합니다.

## 경로와 진입

- 경로: `/restaurants/sns-hot`
- 홈의 `SNS에서 핫한 일본 식당` 우측 더보기 버튼을 누르면 진입합니다.
- 헤더의 뒤로가기 버튼을 누르면 홈으로 이동합니다.

## 화면 구성

- 헤더 제목은 `SNS 맛집 리스트`입니다.
- 정렬 기준은 `인기순`, `최신순`, `별점순`이며 한 번에 하나만 선택합니다.
- 정렬 칩은 헤더 아래에 고정해 목록을 스크롤하는 동안 유지합니다.
- 식당 목록은 공통 `RestaurantCard`를 사용해 이름, 평점, 지역과 음식 종류, 이미지, 소개, 해시태그를 표시합니다.
- 카드 이미지는 최대 5장, 해시태그는 최대 3개를 한 줄로 표시합니다.
- 식당 카드를 누르면 해당 식당 상세 화면으로 이동합니다.
- 목록의 로딩, 오류, 빈 상태와 다음 페이지 조회는 공통 식당 목록 템플릿의 정책을 따릅니다.

## 목록 상태 정책

- 정렬을 변경하면 기존 목록을 비우고 첫 페이지부터 다시 조회하며 화면을 목록 상단으로 이동합니다.
- 식당 상세에서 뒤로 돌아오면 URL에 반영한 정렬 조건, 조회했던 페이지 수, 해당 히스토리 항목의 스크롤 위치를 복원합니다. 캐시가 만료되면 필요한 페이지를 순서대로 다시 조회한 뒤 스크롤을 복원합니다.
- 복원 중에는 일반 무한 스크롤 조회를 막습니다. 추가 조회가 실패하면 기존 카드를 유지하고 재시도 후 복원을 이어갑니다.
- 복원에 필요한 페이지가 캐시에 남아 있으면 백그라운드 재조회 실패와 무관하게 스크롤을 복원합니다. 페이지가 부족한 상태에서 재조회가 실패하면 하단 재시도를 제공하고 성공 후 복원을 이어갑니다.
- 재조회 중에는 하단 감지를 통한 추가 조회를 중단하고, 추가 조회 요청이 진행 중인 요청을 취소하지 않도록 합니다.
- 복원 기록은 마지막 저장 시점 기준 최근 50개만 메모리에 보관하며, 복원 완료 시 삭제합니다.
- SNS 목록은 URL에 장르 값이 포함되어도 항상 `genre=all`로 조회합니다.
- 최초 조회와 추가 조회의 재시도 횟수는 공통 QueryClient 정책에 따라 1회입니다.
- 추가 조회가 최종 실패하면 기존 카드를 유지하고 목록 하단에 오류 안내와 `다시 시도` 버튼을 표시합니다.

## 데이터 계약

- `GET /api/v1/restaurants`를 사용합니다.
- 공통 파라미터는 `type=sns-hot`, `genre=all`, `size=10`입니다.
- `인기순`은 `sort=popular`, `별점순`은 `sort=rating`으로 요청합니다.
- 서버의 최신 등록순 값은 `basic`이므로 화면의 `최신순`은 `sort=basic`으로 변환해 요청합니다.
