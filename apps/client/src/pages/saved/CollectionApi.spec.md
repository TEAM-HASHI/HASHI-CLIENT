# 컬렉션 API 계약

`features/collection`은 공용 endpoint·Query·Mutation·세션 처리·조회 모델과 대상 선택창·커버를 소유한다. 저장 라우트 조립과 지도 핀 adapter는 `pages/saved`에서 관리한다. 화면 구성과 디자인은 [저장 컬렉션 화면 명세](./SavedPage.spec.md)를 따른다.

## 조회 계약

| 데이터                | Endpoint                                             | 입력                                                 | 방식              |
| --------------------- | ---------------------------------------------------- | ---------------------------------------------------- | ----------------- |
| 내 컬렉션·대상 목록   | `GET /api/v1/collections`                            | `restaurantId?`, 숫자 `cursor?`, `size?`             | infinite query    |
| 상세 헤더·수정 초기값 | `GET /api/v1/collections/{collectionId}`             | 양의 안전한 정수 ID                                  | conditional query |
| 저장 식당 목록        | `GET /api/v1/collections/{collectionId}/restaurants` | ID, `sort?`, `placeType?`, 문자열 `cursor?`, `size?` | infinite query    |

- endpoint는 `shared/api/request`의 요청·인증·오류 처리를 사용하며 `AbortSignal`을 전달한다. 요청·응답 타입은 client의 generated OpenAPI에서 파생한다.
- `collectionQueryKeys`에서 정렬·분류를 구분하고 cursor는 `pageParam`으로 관리한다. UI의 `reviews`는 서버 `review`로 변환하고, `all`은 `placeType`을 생략한다.
- 상세·저장 식당은 유효한 ID로 조회한다. 내 목록은 인증 준비 전에 `params=null`로 비활성화한다. 비활성 인수를 수동으로 refetch해도 endpoint를 호출하지 않는다.
- `hasNext=false`는 조회 완료다. 필수 페이지 정보·목록 누락이나 잘못된 cursor는 오류로 전달한다. 추가 요청이 실패하면 기존 페이지를 유지하고 자동 추가 조회를 멈춘 뒤 같은 cursor를 재시도한다.
- 컬렉션 목록 개수는 목록 응답의 `totalCount`, 상세 `총 N곳`은 해당 정렬·분류의 저장 식당 응답 `totalCount`를 사용한다. 저장 식당의 개수는 삭제된 식당을 제외한 전체 페이지 기준이며, 필터 변경 후 응답이 오기 전에는 이전 개수를 표시하지 않는다.

### 조회 모델

- summary는 목록에 필요한 필드만 제공한다. ID를 검증해 화면용 문자열로 변환한다. 누락된 평점·지역·분류·저장 수를 임의로 채우지 않으며 알려진 `visibility`만 표시한다.
- 커버 URL은 최대 세 이미지 슬롯에 대응시키고 빈 슬롯은 fallback용 `null`로 둔다. 알 수 없는 커버 색에는 기존 이미지 fallback을 사용한다.
- 식당 모델은 `thumbnailUrl`과 `thumbnailImage`를 함께 보존하고 표시 시 공통 미디어 선택 계약을 적용한다.

## 접근과 인증 세션

- 내 목록과 모든 쓰기에 bearer 인증이 필요하다. 공유용 상세와 저장 식당 GET은 공개로 요청할 수 있으며 비공개 컬렉션은 서버 응답으로 접근을 제어한다. 서버 404가 도착하면 이전 상세·저장 식당을 숨긴다. 관리·공유는 로그인한 소유자에게 제공한다.
- 비로그인 조회는 회원 조회 캐시와 분리하며 사용하지 않는 비로그인 상세·식당 쿼리는 보관하지 않는다. 로그인 여부 확인 전에는 보호 API를 요청하지 않는다.
- `getAuthSessionVersion`·`subscribeAuthSession`을 사용한다. 목록·상세·저장 식당·이동 사전 조회·핀 key에 세션 버전을 포함한다. 토큰 재발급만으로 버전을 바꾸지 않는다.
- 쓰기 시작 시점의 세션을 요청 전후와 비동기 캐시 작업 후 확인한다. 이전 세션의 늦은 응답은 현재 캐시·안내·화면 복귀에 반영하지 않는다. 계정이 바뀌면 이전 입력·선택·관리/공유 모달과 생성 복귀 상태를 폐기한다.

## 쓰기와 캐시

| 동작           | Endpoint                                                   | 성공 후 캐시                             | 실패 시             |
| -------------- | ---------------------------------------------------------- | ---------------------------------------- | ------------------- |
| 생성           | `POST /api/v1/collections`                                 | 서버 ID로 상세 저장, 목록·대상 목록 갱신 | 입력 유지           |
| 수정·공개 전환 | `PATCH /api/v1/collections/{collectionId}`                 | 상세 반영, 목록·대상 목록 갱신           | 입력·현재 상태 유지 |
| 식당 저장      | `POST /api/v1/collections/{collectionId}/restaurants`      | 상세 및 관련 식당·컬렉션 목록 갱신       | 선택 유지           |
| 식당 해제      | `DELETE /api/v1/collections/{collectionId}/restaurants`    | 상세 및 관련 식당·컬렉션 목록 갱신       | 선택 유지           |
| 식당 이동      | `POST /api/v1/collections/{collectionId}/restaurants/move` | 양쪽 상세 및 식당·컬렉션 목록 갱신       | 선택 유지           |
| 컬렉션 삭제    | `DELETE /api/v1/collections/{collectionId}`                | 삭제 대상 캐시 정리, 목록 갱신           | 현재 화면 유지      |

- 서버 성공 이후에 입력·선택·모달을 정리한다. 이전 상세 조회가 성공 응답을 덮어쓰지 않도록 먼저 같은 상세 조회를 취소한다.
- 식당 관계 변경은 해당 컬렉션의 모든 정렬·분류 목록과 핀, 컬렉션·대상 목록을 갱신한다. 이동은 양쪽에 적용한다. 컬렉션 삭제 시 삭제 리소스의 조회를 취소하고 해당 상세·식당·핀 캐시를 제거한다.
- 컬렉션 오류는 공통 catalog의 `USER-006`~`USER-016`을 따른다. 저장·이동 중복 `USER-012`(409)는 선택·확인창을 유지하고 조회를 갱신한다. 쓰기는 자동 재시도하지 않는다.

## 생성·수정

- 컬렉션명 20자·설명 30자 초과 입력을 제한한다. 초과 시도 안내가 남은 동안에는 제출을 막고, 해당 필드를 제한 내 값으로 수정하면 안내를 해제한다. 한글 조합 중에는 원문을 보존하고 조합 확정 시 제한을 적용한다.
- 서버와 폼은 설명에 공백을 포함해 최대 30자·줄바꿈 금지를 적용한다. 폼은 직접 줄바꿈을 막고 붙여넣기 개행은 공백으로 바꾼다. 서버에서 받은 기존 긴 설명은 자르지 않고 표시하며 제한 내 값으로 고쳐야 저장할 수 있다.
- 이름과 설명은 저장 시 서버의 앞뒤 공백 제거 정책을 따르고 내부 공백은 보존한다. 이름 중복 비교와 수정 변경 감지는 정규화한 값을 사용한다. 생성 요청의 앞뒤 공백 정규화는 서버가 처리한다.
- 생성 기본 색상은 빨강이며 최종 선택한 색상을 전송한다. 수정은 서버 색상과 공개 범위를 초기값으로 사용하며 상세의 소유권·필수 필드를 확인한 뒤 표시한다.
- 이름 중복 검사는 내 컬렉션 목록의 다음 페이지까지 확인하고 수정 대상은 제외한다. 생성하거나 정규화한 이름을 바꿀 때만 확인 중·실패 상태에서 제출을 막고 재시도를 제공한다. 서버 `USER-007`은 이름 중복으로 안내한다.
- 수정 기준값은 첫 응답으로 고정한다. 변경한 필드만 PATCH한다. 생략·`null`은 유지이고 빈 `description`은 설명 삭제다. 배경 조회로 작성 중 입력을 초기화하지 않는다.
- 요청 중 입력·제출·뒤로가기를 막는다. 실패는 인라인으로 안내하고 입력을 보존한다. 성공 응답과 캐시 반영 후 원래 방문 이력과 저장 대상 상태로 돌아간다.

## 저장 대상과 식당 이동

- `CollectionTargetQueryDialog`는 `restaurantId` query에 대한 서버 `saved` 값으로 저장 여부를 표시한다. 확인되지 않은 값에는 저장 여부를 가정하지 않는다. 모달 내부 스크롤로 추가 조회하며 실패하면 기존 대상을 유지하고 재시도한다.
- 컬렉션별 체크 변경은 `저장`으로 확정한다. 저장 흐름에서 생성 화면을 다녀오면 식당과 이전 선택을 복원하고, 생성에 성공하면 새 컬렉션도 선택한다. 자동 저장은 하지 않는다. 식당 상세에서 돌아올 때 기존 탭도 복원한다.
- 이미 반영된 변경은 건너뛰고 부분 실패 시 남은 변경만 재시도한다. 성공한 변경의 캐시는 일괄 갱신하며 식당 저장 수·저장 여부와 관련 컬렉션 조회를 새로 요청한다. 상세 메뉴·리뷰와 랜덤 추천에는 영향을 주지 않는다.
- 이동은 원본 소유권을 확인하고 대상 목록에서 원본을 제외한다. `getCollectionMovePlan`은 대상의 필요한 페이지를 조회해 중복을 확인한다. 모든 선택 ID가 중복임을 확인하면 일찍 종료할 수 있다. 페이지 실패·취소·cursor 순환으로 조회를 끝내지 못하면 이동을 막는다.
- 이동 사전 확인 key는 대상 식당 목록 prefix 아래 `move-plan`과 선택 ID를 포함하며 비활성 상태에서는 보관하지 않는다. 확인 중·실패·모두 중복이면 이동할 수 없고, `이동` 버튼은 확인된 이동 가능 ID만 전송한다. 서버의 최종 409도 처리한다.
- 확인창 취소 시 요청하지 않는다. 요청 중 중복 확인·대상 변경·취소·생성을 막는다. 화면 이탈 후 도착한 응답은 부모 UI를 변경하지 않는다.
- 편집은 소유자 확인 후 해당 정렬·분류에서 20개씩 조회한다. 전체 선택은 현재까지 조회한 식당만 선택·해제한다. 추가 조회 후 새 식당은 미선택 상태이고 전체 선택은 일부 선택으로 바뀐다. 필터·컬렉션 변경 시 선택을 초기화한다.
- 편집의 실패·취소 상태는 선택을 보존한다. 성공하면 실제 이동·해제된 ID만 선택에서 제거해 부분 이동의 중복 식당은 선택 상태로 남긴다. 대상 생성 진입 시 선택 ID·이동창·대상 선택을 보존해 한 번 복원하고 자동 이동은 하지 않는다. 편집 종료는 원래 상세 이력으로, 직접 진입한 경우 해당 상세와 정렬·분류 URL로 돌아간다.

## 삭제·해제

- `CollectionDeleteQueryDialog`는 소유자 상세를 확인한 뒤 컬렉션 삭제 또는 지정 식당의 저장 해제를 요청한다. 대기 중 중복 실행과 취소·Escape 닫기를 막는다. 오류는 인라인으로 안내하고 확인창·선택·기존 데이터를 유지한다.
- 서버 성공과 캐시 반영 후에만 해제된 ID 전달 또는 컬렉션 삭제 후 복귀를 실행한다. 컬렉션 삭제 토스트는 `컬렉션이 삭제되었어요.`이다. 식당 해제와 화면 이탈·세션 변경 후 도착한 응답에는 이 토스트를 표시하지 않는다.
- 지도에서 컬렉션 삭제에 성공하면 `/map`과 컬렉션 목록 패널을 유지한다. 지도 목록에서 삭제하면 패널 높이도 유지한다. 일반 저장 화면에서는 진입한 저장 목록으로 돌아간다.

## 공개 링크 공유

- 현재 origin의 `/saved/collections/{collectionId}`를 `getCollectionDetailPath`와 `copyUrlToClipboard`로 복사한다. 정렬·분류 query와 hash는 포함하지 않는다. 서버의 별도 공유 링크 발급은 필요 없다.
- 공개 컬렉션은 소유권 확인 후 바로 복사한다. 비공개 컬렉션은 공개 전환 확인창을 거쳐 `visibility: public`만 PATCH하고 성공·캐시 반영 후 복사한다. 취소 시 요청하지 않으며 전환 실패 시 확인창·비공개 상태를 유지한다.
- 공개 전환 뒤 복사만 실패하면 공개 상태와 현재 화면을 유지한다. 성공 문구는 `컬렉션 링크가 복사되었어요.`이고 실패 문구는 `링크를 복사하지 못했습니다. 다시 시도해주세요.`다. 토스트 큐를 정리한 뒤 안내하며 기존 공유 진입점에서 재시도할 수 있다.
- 복사·전환 대기 중 중복 요청을 막고 화면 이탈·세션 변경 후 도착한 응답은 토스트나 종료 콜백을 실행하지 않는다.

## 지도 계약

- `CollectionMapQueryPage`는 기존 지도 viewport와 컬렉션 화면을 조립한다. 지도·식당 상세·메뉴의 저장 버튼은 `CollectionTargetQueryDialog`를 재사용한다. 지도 패널 복귀 상태는 같은 인증 세션에서만 복원한다.
- 선택한 컬렉션의 전체 핀은 `GET /api/v1/collections/{collectionId}/map-markers`로 조회한다. 이 요청은 목록의 페이지·정렬·분류와 독립적이다. 좌표가 없는 식당은 목록에만 표시하며 좌표가 만료되면 지도에서 핀과 좌표 출처를 제거한다. 상세·핀 조회 오류 시 기존 핀을 숨기고 재시도를 제공한다.
- 컬렉션 핀은 커버 팔레트와 HDS `SaveIcon`을 사용한다. `COLLECTION_PIN_COLORS`에서 주황·노랑·초록은 커버 전경색, 빨강·파랑·보라는 커버 배경색을 사용한다. [핀 디자인](https://www.figma.com/design/UHaom01PvoRx2wRCYa1kS1/Hashi.kr?node-id=8317-38305)
- 지도 북마크 목록에서 진입하면 지도 탭을 유지한다. 일반 상세에서 진입하면 원래 저장 탭 또는 마이 탭에 맞춰 표시한다. 자세한 진입·닫기 동작은 [저장 컬렉션 화면 명세의 지도 연결](./SavedPage.spec.md#지도-연결)을 따른다.

## 검증 기준과 남은 확인

- API·Query 검증은 요청 경로·인증·cursor·`AbortSignal`, 필터별 key와 전체 개수, 잘못된 응답·초기 및 추가 조회 실패, PATCH 필드 생략·빈 설명, 중복 이동·409·404, 관계 변경 후 캐시와 계정 격리를 다룬다.
- 제품 라우트 검증은 공개 상세, 실제 형식의 식당 ID 이동과 복귀, 생성·수정·삭제 후 재조회와 복귀, 편집 선택과 부분 이동, 공개 전환 후 복사 실패를 다룬다. 자동 검증은 인증·컬렉션 HTTP 응답 대역을 사용한다.
