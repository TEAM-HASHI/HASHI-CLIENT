# 저장 컬렉션 퍼블리싱

## 목적과 범위

`/saved`의 인증된 사용자에게 컬렉션 목록·상세를 표시하는 퍼블리싱이다.
별도 목 데이터로 동작하며 API와 영구 저장을 연결하지 않는다.

기능 근거는 최신화한 HASHI-PLAN `main` (`6f2c99c`)의
SAVED_COLLECTION_LIST, SAVED_COLLECTION_SAVE, SAVED_COLLECTION_MANAGE,
SAVED_COLLECTION, SAVED_COLLECTION_SHARE 명세다. 충돌 시 사용자 확정 정책을 우선한다.

작업 브랜치는 `feat/HASHI-206-collection-list`이며, 미병합 #209의 head
`22b3fc4`에서 분기했다. PR base는 `feat/HASHI-214-drag-panel`로 지정한다.
기존 `feat/HASHI-206-collection-page` 브랜치는 보존했다.

## 데이터와 상태

- `collectionMocks.ts`: 컬렉션, 식당, 저장 시각, 세 커버 이미지 슬롯을 명시한다.
- `selectCollections`: 최근 생성 순으로 고정한다. 화면에는 최신순만 표시한다.
- `selectRestaurants`: 삭제·비노출·누락 식당을 제외한 후 분류와 정렬을 적용한다.
- 정렬은 최신순/별점순/리뷰순, 분류는 전체/음식점/카페/주점이다.
- 상세 기본값은 최신순/전체이며, 정렬과 분류는 서로 유지된다. 선택 즉시 적용하고
  메뉴를 닫으며 키보드 선택·Escape·바깥 클릭 닫기·포커스 복귀를 지원한다.
- 목록·상세는 같은 `/saved` 안에서 전환한다. 새로고침 시 목 데이터는 초기값이다.
- 빈 목록은 0개와 생성 항목을, 빈 상세는 컬렉션 정보와 0곳을 유지한다.
- 긴 이름은 행에서 줄바꿈하며 HDS Header 제목은 말줄임과 원문 title을 제공한다.

## 지도 담당자 연결

`지도로 보기`는 기존 `/map`에 `CollectionMapState`를 location.state로 전달한다.
필드는 `{ collectionId, sort, category }`이며 `isCollectionMapState`로 검증한다.
지도 모드에서는 `BottomNavigationLayout`이 저장 탭을 활성화한다.
현재 base의 지도 경로는 ComingSoon 상태이며 이 PR에서 교체하지 않는다.

`CollectionDragPanelContent`는 내비게이션과 safe area를 제외한 relative 부모
컨테이너에 배치한다. `availableHeight`는 그 부모의 실측 높이다. `data`, `view`,
`onViewChange`, `onRestaurantSelect`, `onClose`를 지도 담당자가 연결한다.
`onClose`는 컬렉션 모드를 해제하고 기본 지도를 복원할 지점이다.
목 식당 ID를 실제 식당 상세 API에 전달하지 않는다.

목록의 최초 높이는 실측 콘텐츠에 따라 234~374px, 상세는 393px이다.
손잡이를 포함하고 내비게이션 84px은 제외한 값이다. 내비게이션까지 합치면
목록은 사용자 확정 기준 318~458px, 상세는 Figma `8317:40117` 기준 477px이다.
최대 확장 높이는 가용 높이
에서 12px을 뺀 값이며 작은 화면에서 제한한다. 패널을 접어도 선택과 정렬·분류를
유지한다. PR 1에는 고정 하단 액션이 없어 footer를 사용하지 않는다. 긴 설명과
낮은 화면에서도 모든 정보에 접근하도록 요약·필터·목록을 같은 body 스크롤에
배치한다. 드롭다운은 portal로 패널 바깥 잘림을 방지한다.

## 재사용과 후속 PR

HDS Header, BottomNavigation, Thumbnail/ImageFallback, Button, IconButton,
OptionItem, DragPanel과 기존 아이콘을 사용하며 공통 패키지는 수정하지 않는다.
커버 색상 중 기존 토큰에 없는 값은 Figma `collection_cover`의 확인된 색상을
이름 있는 페이지 상수로 관리한다. 예시 사진은 없으므로 HDS fallback을 사용한다.

PR 1에서 더보기 아이콘은 장식용 슬롯이며 새 컬렉션 만들기는 비활성화했다.
PR 2는 생성·수정하기·저장 UI와 수정 폐기 확인을 연결한다.
PR 3은 편집하기·식당 선택·이동·삭제·컬렉션 삭제·링크 복사·헤더 공유·확인 모달·
토스트를 연결한다. 공개 링크 조회는 제외한다.
비공개 공유는 즉시 복사 명세보다 사용자 확정 정책을 우선하여 공개 전환 확인
모달을 거친다. 실제 공유 URL 생성·복사는 연결하지 않는다.

## PR 2: 생성·수정·저장 (HASHI-221)

- 브랜치 `feat/HASHI-221-collection-save`는 PR 1의 `226b9ee`에서 분기했다.
  PR을 생성할 때 base는 `feat/HASHI-206-collection-list`로 지정한다.
- 작업 전 두 저장소를 최신화했다. HASHI-PLAN은 `1c981e5`이며 SAVED 명세는
  PR 1 기준에서 변경되지 않았다. PLAN 파일을 직접 수정하지 않는다.
- `CollectionForm`은 사용자 승인 페이지 조합이다. 생성과 정보 수정을 함께
  표현하며 HDS Header, IconButton, InputField, Chip, Button, Dialog를 재사용한다.
- 생성은 앞뒤 공백을 보존하고 수정은 제거한다. 공백만 있는 이름은 거절한다.
  이름 20자·설명 100자 제한은 `collectionMutations.ts` 상수로 관리한다.
  한글 조합이 끝난 후 길이를 제한한다. 중복 이름은 제출하지 않는다.
- 생성 초기 색상은 미선택, 공개 범위는 공개다. 디자인의 초기 초록 선택보다
  SAVED 명세를 우선한다. 수정 시 기존 값을 채우며 변경이 있어야 저장된다.
- 사용자 승인 문구: `이미 사용 중인 컬렉션명이에요.`,
  `변경 사항을 저장하지 않고 나갈까요?`, `저장하지 않은 변경 사항은 사라져요.`.
  수정 폐기 버튼은 `뒤로가기`·`계속하기`다. 헤더·브라우저 뒤로가기를 모두 처리한다.

  식당 상세·지도 버튼에 연결하지 않고 fixture의 `?save=sushi`로 검증한다.
  한 컬렉션만 선택하며 이미 저장한 대상은 체크 표시와 함께 비활성화한다.
  취소는 데이터를 변경하지 않는다. 생성 후 목록으로 돌아와도 자동 선택하지 않는다.
- `CollectionDataProvider`는 라우트 간 목 상태만 유지한다. 새로고침하면 초기화한다.
  실제 API·총 저장 수 응답·저장 성공 토스트는 연결하지 않는다.
  생성·수정·저장 상태 변경은 순수 함수로 분리하고 가상 서비스는 만들지 않는다.
- 지도 담당자는 같은 목 상태의 `data`와 `onDataChange`를
  `CollectionDragPanelContent`에 연결할 수 있다. 지도 자체는 변경하지 않는다.

## PR 3: 식당 관리·삭제·공유 (HASHI-222)

- PR 2는 `e754d15`로 커밋·푸시했다. PR 3 브랜치는
  `feat/HASHI-222-collection-manage`이며 PR base는 `feat/HASHI-221-collection-save`다.
- 승인된 `CollectionEditor`에서 일반 목록·지도 패널의 편집 흐름을 함께 처리한다.
  기존 식당 행과 HDS Header, Checkbox, Button, Dialog를 조합하며 공통 패키지는
  변경하지 않는다. 원형 24px 선택 표시는 페이지 내부 Checkbox 스타일로 적용한다.
- 목록 더보기는 링크 복사·수정하기·삭제하기, 상세 더보기는 편집하기·삭제하기다.
  상세 공유는 별도 헤더 아이콘이며 식당 더보기는 이동하기·삭제하기다.
- 편집은 현재 정렬·분류로 표시된 식당을 대상으로 한다. 전체·개별·일부 선택을
  지원하고 선택 수를 이동·삭제 버튼에 표시한다. 뒤로가기·닫기는 선택을 폐기한다.
- `CollectionTargetDialog`는 PR 2 저장 대상 콘텐츠를 이동에도 재사용한다.
  현재 컬렉션은 이동 대상에서 제외하며 하나만 선택한다. 생성 후 자동 선택하지 않는다.
- 단일 중복 이동은 목록·선택을 유지한다. 여러 식당 이동에서는 중복을 원래
  컬렉션에 남기고 이동 가능한 식당만 옮긴다. 중복 수를 안내하며
  성공 후 편집 화면에 남는다. 취소는 선택과 목록을 유지한다.
- 식당 삭제는 확인 후 해당 저장 관계만 제거한다. 컬렉션 삭제는 해당 컬렉션의
  저장 관계만 제거하고 목록으로 돌아간다. 식당 원본·다른 컬렉션은 유지한다.
  `getSavedRestaurantIds`로 사용자 저장 관계의 중복을 제거해 마지막 관계 소멸을
  검증한다. 서버의 전체 저장 수나 가상의 API 응답은 만들지 않는다.
- 비공개 공유는 Figma 확인 모달을 거쳐 목 공개 상태만 변경한다. 공개 링크 복사도
  미연결 안내만 한다. 실제 URL 생성·클립보드 호출·복사 성공 토스트는 제공하지 않는다.
  이는 기존 명세의 즉시 복사보다 사용자 확정 정책을 우선한 처리다.
- HDS Toast를 재사용하여 컬렉션 삭제와 공유 미연결 상태를 안내한다.
  실제 API 실패·지도 핀 복원·공개 링크 조회는 계속 범위 밖이다.
