# 회원탈퇴 페이지 명세

Jira: HASHI-204

API 연동: HASHI-226

## 목적

- 사용자가 회원 탈퇴 전에 계정 복구 불가, 재로그인 제한, 리뷰·사진 보존 및 작성자 익명화 안내를 확인할 수 있게 합니다.
- 탈퇴 동의 여부에 따라 탈퇴 버튼의 활성 상태를 제어합니다.
- 동의 후 회원탈퇴 API를 호출하고, 성공 시 인증과 사용자 캐시를 정리합니다.

## 경로

- 경로: `/withdrawal`
- 경로 상수: `ROUTES.withdrawal`
- 접근 권한: `authOnly`
- 하단 내비게이션: 없음

## 현재 동작

- [x] 헤더와 뒤로 가기 버튼을 표시합니다.
- [x] 탈퇴 전 확인 사항을 표시합니다.
- [x] 확인 동의 체크박스를 표시합니다.
- [x] 동의 전에는 탈퇴 버튼을 비활성화합니다.
- [x] 동의 후에는 탈퇴 버튼을 활성화합니다.
- [x] 뒤로 가기와 돌아가기 버튼은 마이페이지로 이동합니다.
- [x] 탈퇴 버튼을 누르면 `DELETE /api/v1/users/me`를 호출합니다.
- [x] 요청 중 동의 체크박스와 뒤로가기·돌아가기·탈퇴 버튼을 비활성화합니다.
- [x] 동기 잠금으로 같은 렌더 주기의 연속 클릭도 한 번만 요청합니다.
- [x] 요청 중 앱 내부 이동과 브라우저 뒤로가기를 차단합니다. 문서 새로고침·닫기는 브라우저의 이탈 확인을 사용하며 강제 종료까지 막을 수는 없습니다.
- 최신 피그마 `8317:34309`의 문구대로 계정 이용·복구, 리뷰·사진 익명화, 포인트 소멸, 예약·환불 제한, 법정 보관 정보의 안내 카드 5개를 표시합니다.
- 작은 화면에서 동의 문구가 줄바꿈되어도 체크박스 도형은 26px 크기를 유지합니다.
- 본문 시작 위치는 기존 합의대로 유지하며, 페이지의 `main` 랜드마크는 `RootLayout`에서 제공합니다.

## 데이터 연동과 예외

- 개발 Swagger와 서버 `UserController`, `UserWithdrawalService`, `ReservationWithdrawalBlocker`, `AuthAccountPortImpl`을 확인했습니다.
- `DELETE /api/v1/users/me`: 본문 없이 Bearer 인증과 `credentials: include`로 요청합니다. 성공은 `200 / USER-204`, `data: null`입니다.
- 공통 request wrapper의 401 재발급·원 요청 1회 재시도는 유지합니다. mutation 자체는 자동 재시도하지 않습니다.
- 성공 시 전체 Query 캐시와 인메모리 인증을 정리하고 `ROUTES.loginRequired`로 replace 이동합니다. 추가 확인 모달과 성공 토스트는 제공하지 않습니다.
- `USER-005`(회원 없음) 또는 재발급 이후에도 인증이 유효하지 않은 401은 인증·캐시를 정리하고 로그인 화면으로 이동하며 별도 오류 토스트는 표시하지 않습니다. 일반 404는 회원 없음으로 취급하지 않습니다.
- `409 / RESERVATION-008`은 서버가 내려준 메시지를 그대로 토스트로 표시합니다. 예약 상태의 판단과 안내 문구는 서버가 담당하며, 프론트 공통 오류 목록에 문구를 중복 등록하지 않습니다.
- 그 외 실패는 공통 오류 안내를 표시하고 현재 화면·동의 상태·사용자 캐시를 유지합니다. 요청 종료 후 같은 버튼으로 재시도할 수 있습니다.
- 탈퇴 클릭 시 세션 버전을 캡처합니다. 전송 전 버전이 바뀌면 요청하지 않으며, 응답 대기 중 새 로그인·온보딩 세션이 시작되면 이전 응답은 새 인증·캐시·화면을 변경하지 않습니다.
- 요청한 세션 자체가 재발급 또는 BFCache 인증 재확인 실패로 만료된 경우에는 응답 처리를 완료합니다. 직접 로그아웃하거나 다른 로그인·온보딩 세션을 거친 뒤 미인증 상태가 되면 이전 응답의 캐시 정리·화면 이동·오류 안내는 무시합니다.
- 이탈 차단은 요청 시작 당시의 인증 세션에만 적용합니다. 새 로그인·온보딩으로 세션이 바뀌면 이전 요청이 새 세션의 이동을 막지 않습니다.
- 토큰 폐기, 리뷰·사진 보존과 익명화, 컬렉션 삭제 및 포인트 소멸은 서버가 담당합니다. 프론트에서 데이터를 개별 삭제하거나 익명 닉네임을 배정하지 않습니다.

## 후속 작업

- 환불 진행 건의 탈퇴 제한은 서버팀 확인이 필요합니다. 사용자 요청에 따라 안내는 디자인 문구를 유지하며, 실제 탈퇴 차단은 현재 서버의 예약 상태 검사에 따릅니다. 프론트에서 별도 환불 제한을 추정하거나 추가하지 않습니다.
- 공통 하단 액션바 컴포넌트 병합 후 `WithdrawalBottomBar` 교체
- 실제 탈퇴가 허용된 테스트 계정으로 개발 서버 종단 검증. 실제 계정을 임의로 탈퇴시키지 않습니다.
- 부모 로그아웃 PR의 Web Locks 미지원 브라우저 대응은 별도 후속 작업을 따릅니다.

## 검증 기준

- 단순 표시·디자인 테스트 대신 중복 요청·이탈 방지, 예약 제한 후 재시도, 인증·캐시 정리, 새 세션 보호를 검증합니다.
- 393px 및 320px 화면에서 문구, 체크박스 크기, 버튼 겹침 여부를 확인합니다.
- 서버 실패 후 동의 상태와 캐시가 유지되고, 성공·회원 없음·인증 종료 시 로그인 화면으로 이동하는지 확인합니다.
- 타입 검사, 관련 ESLint, `git diff --check`를 실행합니다.
