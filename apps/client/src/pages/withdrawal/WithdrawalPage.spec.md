# 회원탈퇴 페이지 명세

Jira: HASHI-204

## 목적

- 사용자가 회원 탈퇴 전에 계정 복구 불가, 재로그인 제한, 리뷰·사진 보존 및 작성자 익명화 안내를 확인할 수 있게 합니다.
- 탈퇴 동의 여부에 따라 탈퇴 버튼의 활성 상태를 제어합니다.
- 서버 API가 구현되기 전까지 실제 탈퇴 처리는 준비중 안내로 대체합니다.

## 경로

- 경로: `/withdrawal`
- 경로 상수: `ROUTES.withdrawal`
- 접근 권한: `authOnly`
- 하단 내비게이션: 없음

## 현재 동작

- [x] 헤더와 뒤로 가기 버튼을 표시합니다.
- [x] 탈퇴 전 확인 사항을 표시합니다.
- [x] 확인 동의 체크박스를 표시합니다.
- [x] 동의 전에는 탈퇴 버튼을 비활성화합니다.
- [x] 동의 후에는 탈퇴 버튼을 활성화합니다.
- [x] 뒤로 가기와 돌아가기 버튼은 마이페이지로 이동합니다.
- [x] 탈퇴 버튼을 누르면 API 미연동 상태를 안내합니다.
- 리뷰와 첨부 사진은 보존하며 작성자를 기본 프로필 이미지와 익명 닉네임으로 표시한다는 최신 기획 정책을 안내합니다. 피그마의 즉시 삭제 문구 대신 최신 기획을 따릅니다.
- 작은 화면에서 동의 문구가 줄바꿈되어도 체크박스 도형은 26px 크기를 유지합니다.
- 본문 시작 위치는 기존 합의대로 유지하며, 페이지의 `main` 랜드마크는 `RootLayout`에서 제공합니다.

## 후속 작업

- 공통 하단 액션바 컴포넌트 병합 후 `WithdrawalBottomBar` 교체
- `DELETE /api/v1/users/me` 연동
- 방문 완료 또는 취소로 종료되지 않은 예약이 있으면 서버 응답에 따라 탈퇴 제한 안내
- 요청 중 뒤로가기·돌아가기·탈퇴 버튼·동의 체크박스 비활성화 및 중복 요청 방지
- 탈퇴 성공 후 인증 정보와 사용자별 캐시 제거 및 로그인 화면 이동
- 이미 탈퇴했거나 회원이 없는 응답의 인증 정리 및 로그인 화면 이동
- 요청 실패 시 동의 상태와 화면을 유지하고 오류 안내 및 재시도 제공
- API 연동 시 중복 요청 방지·실패 후 상태 유지·인증 및 캐시 정리 등 핵심 로직 테스트 추가

## 검증 기준

- 단순 체크박스 활성화·준비중 다이얼로그 표시 테스트는 제거하고 현재 퍼블리싱은 수동 확인합니다.
- 393px 및 320px 화면에서 문구, 체크박스 크기, 버튼 겹침 여부를 확인합니다.
- 동의 체크·해제에 따른 버튼 활성화와 준비중 안내를 확인합니다.
- 타입 검사, 관련 ESLint, `git diff --check`를 실행합니다.
